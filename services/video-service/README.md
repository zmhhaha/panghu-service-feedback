## 历史观察与最新复测

<a id="vid-001"></a>
### VID-001：从已采用镜头直接导出MP4

**10月30日：** 站内导出的是可编辑素材，成片需要外部合成。用户完成画面后还要处理镜头时长、字幕与编码，制作流程未闭合。

**11月4日：** 已实际下载网站原生完整有声MP4草稿，174秒，H.264视频与AAC音轨，全文件解码通过；单镜首镜也已在站内播放至结束。原生完整草稿可取得，旧能力缺口已明显改善；正式导出与人工精确校时未完成。

建议先支持按已采用版本进行项目预览与MP4导出，清楚区分素材包、静音视频和有声视频。验收时应能从8个已采用镜头直接下载可播放文件，核对镜头顺序、时长、字幕、画幅及声音状态；不能只以ZIP素材导出成功代替成片验证。

<a id="vid-002"></a>
### VID-002：不同镜头连续操作出现项目版本冲突

**10月30日：** 连续生成不同镜头时，曾出现“项目已有更新”，部分操作需要重新读取状态后重试。不同镜头的正常操作受到项目级异步更新影响。

**11月4日：** 在第4、5镜图解异步生成期间保存第7镜旁白，实际再次出现“项目已有更新。你的草稿已保留，请重新载入最新内容后再保存。”同步最新项目、重新打开表单后保存成功。草稿保留已有帮助，但其他镜头的正常异步生成仍会打断当前编辑，需要额外恢复操作；旧任务迟到覆盖等其他边界未全面验证。

建议减少无关镜头之间的版本冲突，并自动同步任务结果。验收时连续或交错操作两个镜头，应能各自保留结果；迟到结果不得覆盖较新的用户选择，发生真实冲突时应说明受影响的镜头和恢复方法。

<a id="vid-003"></a>
### VID-003：批量制作操作不足

**10月30日：** 8个镜头需要逐个生成、检查和采用，重复点击较多。

**11月4日：** 已使用8图解、8配音、8草稿共24项批量制作；页面有逐项结果、失败项勾选补做和集中审阅采用。第3镜仅重试失败草稿仍失败，之后简化图解、复用原配音A1，成功生成并下载MP4，第4镜同法恢复。第1、2、6镜已通过集中审阅采用确切原始候选；其余镜头采用简化版本，8镜均已采用，并取得完整有声草稿。批量、集中采用及正常页面的局部恢复已部分验证。

建议保留已有批量及确切候选采用流程，增强失败时的针对性恢复建议。验收时成功项不因批量重试而重复生成，补做与采用范围应准确；一镜失败不应要求重做整个项目。

<a id="vid-004"></a>
### VID-004：生成过程反馈不足

**10月30日：** 拆分镜头等待较久，界面主要显示“制作中”，不容易判断当前在处理什么。

**11月4日：** 逐镜逐步骤进度已改善，首轮显示“部分未完成 · 19/24项完成或复用”。8个图解、8个配音均成功；第1、2、6镜草稿成功，第3、4、5、7、8镜草稿失败。失败不阻断后续镜头，成功内容保留。

失败卡仅写“本步骤未完成，请检查已有结果后手动补做。”项目成片列表写“动态图解处理未完成，请重新读取状态并检查当前内容、配音和时序。”第3镜直接重试仍失败；通过正常页面简化为图解2、保留原配音A1后，10:34确认MP4成功并下载，第4镜同法恢复。该局部恢复有效，但不能据此确定原始失败根因；页面仍未说明应修改图解、配音还是时序。其余失败镜头已采用简化图解，整片结果见[本次实测](retest-2026-11-04.md)。

整片草稿从10:48提交到11:02下载约14分钟，期间主要显示“制作中”，缺少渲染、合成等子阶段与完成数。最终成功不消除等待期间难以判断进展的问题。

建议保留已有逐镜进度，并为整片显示当前子阶段、已用时间及完成数，补充可理解的失败原因、受影响步骤、脱敏诊断标识和针对性恢复入口。验收时用户离开再返回能辨认原任务状态；模拟图解、配音、时序及渲染失败，应分别给出相应恢复建议。补做单项不得重新制作无关成功内容。

<a id="vid-005"></a>
### VID-005：制作规格约束不清楚

**10月30日：** 在视觉方向中写了1920×1080，但实际生成的SVG是1280×720。文字要求与生成资产尺寸不一致；外部转成1080p视频不能算站内已满足该规格。

**11月4日：** 输入仍要求1080p，已下载单镜及完整草稿均为1280×720、24fps。当前路径未看到清晰的分辨率选择或草稿与正式规格区别说明；正式输出规格尚未验证，不能直接断言正式输出也只有720p。

建议将比例、分辨率、字体和配色设为正式参数，并在生成前后显示实际值。验收时选定规格应反映到资产；若画面素材与最终视频分辨率有意不同，应清楚解释转换规则。

<a id="vid-006"></a>
### VID-006：预览和采用状态需要更明确

**10月30日：** 异步更新时预览状态曾跳动，用户不容易辨认正在看的版本与最终导出的版本。

**11月4日：** 确切候选审阅和采用已分开。早期单镜产物列表中多个文件均显示“MP4草稿 · 无字幕”，没有直接标镜头名，单镜播放器样本显示“文稿版本 —”；后续整片播放器明确显示文稿版本59。未修改文稿时，其他镜头生成也令旧草稿显示“项目已有后续修改”，不容易判断当前镜头是否真正过期。

建议为单镜草稿显示镜头序号、名称、图解版本、配音版本和生成时间；仅在相关内容变化时提示该草稿过期，说明其他项目变化的影响范围。验收时连续生成8镜头后，无需逐个打开播放器即可找到指定镜头并判断其版本是否匹配。新候选不得悄悄改变已采用版本。

**11月4日：** 单镜原生视频确认图形逐步出现，完整草稿已在站内从0播放至174秒结束。8镜顺序正确，7处边界前后约0.15秒抽帧为直接切换，未在样本中发现黑屏错序；人工精确音画同步未完成。画面仍有连线可读性及尾卡问题，见VID-012。

<a id="vid-008"></a>
### VID-008：逐镜头配音与有声成片

**10月30日：** 可见工作台有旁白文本，但未看到语音生成、试听或音轨编辑入口，提出以下流程建议：

**旁白文稿 → 逐镜头中文TTS或上传配音 → 试听并采用 → 按实际音频时长协调镜头和字幕 → 项目预览 → 带声音MP4。**

**11月4日：** 已使用项目统一音色“云健”，8个配音候选成功；原生WAV可下载，完整174秒MP4草稿含24kHz单声道AAC音轨且全文件解码通过。8镜源配音已通过本地ASR识别主要语义，专名读音仍有不确定性，未声明主观听感或人工精确校时通过。正式导出未完成。当前成片页面明确“不附加字幕”，因此可选中文字幕继续作为功能建议，不描述为已有字幕功能故障。

点击正式“导出MP4”后，页面明确要求先完成动态时序人工试听核对。本次没有正式产物；这是验证边界，不列为服务故障。

支持音色、语速、技术缩写读音修正、单段重新生成和上传替代配音。验收时应显示实际音频时长，画面不得截断旁白，字幕与当前采用的音频对应；缺失或过期音频应明确提示，静音输出由用户明确选择。有声MP4还应实际检查音轨和播放效果，而不只检查文件是否生成。

<a id="vid-009"></a>
### VID-009：音频版本与局部更新

**11月4日：** 候选配音有A1等版本标识、试听选择及独立采用入口。使用者主动精确化第7镜旁白后，旧图解1被标记过期，仅该镜配音重生成并采用A2，其他镜头仍用A1，局部失效提示、重生成和采用部分验证。这次文字修订不是服务生成错误；语速变更、旧任务迟到等边界尚未全面覆盖。

建议音频候选关联镜头、旁白版本、生成参数和内容摘要，试听与采用分别记录，历史可追溯。修改单个镜头旁白时，只标记该镜头相关音频及下游时长、字幕需要更新，不要求重做整个项目。

验收时改变一个镜头的文稿或语速，应准确标记受影响内容；旧任务迟到不能覆盖新选择，其他镜头已采用的音频保持可用。

<a id="vid-010"></a>
### VID-010：背景音乐和基础混音

**11月4日：** 此次制作路径未看到背景音乐和混音入口。保留功能建议，不据此推断全站不存在或已有功能发生故障。

## 11月4日新增观察

<a id="vid-011"></a>
### VID-011：空镜头选择误报连接中断

新建项目拆分后，批量制作镜头默认均未选中，“核对制作范围与任务上限”仍可点击。点击后显示“连接中断，尚未确认操作结果。可重新读取状态，或重试同一个操作。”勾选8镜头后同一核对操作成功；旧错误在制作成功开始后仍保留，需手动关闭。

建议无选择时禁用按钮或提示“请至少选择一个镜头”，补齐后成功操作应清理过期提示。验收覆盖空选择、单镜、多镜和真实网络中断，不能把遗漏选择报为网络问题，避免用户无效刷新或重复操作。

<a id="vid-012"></a>
### VID-012：连线避让、标签与尾卡可读性

从原生MP4提取的画面可见：第1镜17秒，DSH到“一切皆插件”的竖线穿过“大模型”卡片，关系起点容易误读，另一条斜线穿过“承载这些能力”标签；第2镜21秒，“再依据文件回答”标签挤近右卡片；第6镜21秒，“没有待处理工作”被斜线穿过，水平关系标签也拥挤。截图见[本次实测](retest-2026-11-04.md)。

完整草稿中，第3镜简化后的竖线仍穿过“提供/插件提供”文字。尾卡来源在173秒仍淡，到173.75秒才清楚，174秒即结束；只有仓库名`deepseek-ai/deepseek-harness`，没有完整URL与核对日期。

建议连线绕开无关节点与文字，长关系标签换行或扩大间距，箭头明确连接对应节点边界。验收第1、2、3、6镜的全部关键帧：无连线穿过无关卡片，无文字被线覆盖，标签不碰边、不出框，缩小播放仍能辨认关系。尾卡应显示完整来源URL和核对日期，清晰状态至少保持3～5秒，正常播放能够读完。

## 已有提案与状态边界

上述音频流程已于2026-10-30记录到 [OpenSpec服务](https://openspec.panghuer.top/) 的 `armbianbegin` 项目，变更标识为 `add-video-workbench-audio-production`，记录有19项待办及验收条件，历史操作已完成规格校验。访问具体项目可能需要登录，不能把该服务首页链接视为公开提案全文。

既有 `add-svg-html-video-workbench` 首版规格明确将TTS、MP4和音画同步列为后续能力，保留该历史范围。11月4日已取得部分实现的用户路径证据，状态按具体复测更新；“提案创建及校验通过”仍不等于“功能实现及验收通过”，单镜成功也不自动证明整片通过。更多渠道记录见[OpenSpec使用记录](../openspec/README.md)。

维护者修复后，可在本仓库补充实现版本、部署日期、对应条目和真实用户流程的复测结果，再更新状态。
