## 体验范围与产物归属

制作任务为 DeepSeek Harness（DSH）架构解析。工作台完成了8个镜头、180秒文稿、SVG画面候选、明确采用和可编辑ZIP素材导出，页面上的中文标题及架构图排版总体可用。

最终3分钟、1080p、24fps的中文字幕MP4由外部工具合成，**不是网站原生MP4导出成功记录**。本地文件核查只有视频流和数据流，没有音频流。

## 历史观察

<a id="vid-001"></a>
### VID-001：从已采用镜头直接导出MP4

当时站内导出的是可编辑素材，成片需要外部合成。用户完成画面后还要处理镜头时长、字幕与编码，制作流程未闭合。

建议先支持按已采用版本进行项目预览与MP4导出，清楚区分素材包、静音视频和有声视频。验收时应能从8个已采用镜头直接下载可播放文件，核对镜头顺序、时长、字幕、画幅及声音状态；不能只以ZIP素材导出成功代替成片验证。

<a id="vid-002"></a>
### VID-002：不同镜头连续操作出现项目版本冲突

连续生成不同镜头时，曾出现“项目已有更新”，部分操作需要重新读取状态后重试。不同镜头的正常操作受到项目级异步更新影响。

建议减少无关镜头之间的版本冲突，并自动同步任务结果。验收时连续或交错操作两个镜头，应能各自保留结果；迟到结果不得覆盖较新的用户选择，发生真实冲突时应说明受影响的镜头和恢复方法。

<a id="vid-003"></a>
### VID-003：批量制作操作不足

8个镜头需要逐个生成、检查和采用，重复点击较多。

建议提供“生成全部缺失画面”“重试失败镜头”和明确选择范围的批量采用。验收时能看到各镜头结果与失败项，成功项不因批量重试而重复生成；批量采用前能核对实际候选。

<a id="vid-004"></a>
### VID-004：生成过程反馈不足

拆分镜头等待较久，界面主要显示“制作中”，不容易判断当前在处理什么。

建议显示当前阶段、已等待与已执行时间、成功/失败数量、可理解的失败原因，以及项目级任务列表。验收时用户离开再返回能辨认原任务状态，不需要通过重复提交确认任务是否存在。

<a id="vid-005"></a>
### VID-005：制作规格约束不清楚

在视觉方向中写了1920×1080，但实际生成的SVG是1280×720。文字要求与生成资产尺寸不一致；外部转成1080p视频不能算站内已满足该规格。

建议将比例、分辨率、字体和配色设为正式参数，并在生成前后显示实际值。验收时选定规格应反映到资产；若画面素材与最终视频分辨率有意不同，应清楚解释转换规则。

<a id="vid-006"></a>
### VID-006：预览和采用状态需要更明确

异步更新时预览状态曾跳动，用户不容易辨认正在看的版本与最终导出的版本。

建议显示“正在预览”“当前采用”“生成中”等独立状态，支持候选对比。验收时新候选完成不应悄悄改变已采用版本，导出前应能核对各镜头的采用结果。

## 后续能力建议

<a id="vid-007"></a>
### VID-007：增加随讲解推进的架构动画

本次生成的主要是完整静态架构画面。建议支持模块逐个出现、箭头流动和当前步骤高亮，让讲解节奏与画面变化对应。

这是一项产品建议，不是已完成动画功能的故障报告。可用“模型调用工具”的单个镜头验证：步骤依序高亮、关键标签始终可读，预览与导出效果一致。

<a id="vid-008"></a>
### VID-008：逐镜头配音与有声成片

当时可见工作台有旁白文本，但未看到语音生成、试听或音轨编辑入口。建议第一阶段打通：

**旁白文稿 → 逐镜头中文TTS或上传配音 → 试听并采用 → 按实际音频时长协调镜头和字幕 → 项目预览 → 带声音MP4。**

支持音色、语速、技术缩写读音修正、单段重新生成和上传替代配音。验收时应显示实际音频时长，画面不得截断旁白，字幕与当前采用的音频对应；缺失或过期音频应明确提示，静音输出由用户明确选择。有声MP4还应实际检查音轨和播放效果，而不只检查文件是否生成。

<a id="vid-009"></a>
### VID-009：音频版本与局部更新

建议音频候选关联镜头、旁白版本、生成参数和内容摘要，试听与采用分别记录，历史可追溯。修改单个镜头旁白时，只标记该镜头相关音频及下游时长、字幕需要更新，不要求重做整个项目。

验收时改变一个镜头的文稿或语速，应准确标记受影响内容；旧任务迟到不能覆盖新选择，其他镜头已采用的音频保持可用。

<a id="vid-010"></a>
### VID-010：背景音乐和基础混音

建议第二阶段提供背景音乐上传、音量、裁剪、淡入淡出，旁白出现时自动降低音乐音量，并处理整体响度及削波。

验收时人声清楚、音量变化平滑，导出与预览一致；不使用背景音乐的项目也能正常完成有声视频流程。
