## 本次调研与实际结果

主题为“DSH、LangGraph与AutoGen：文件问答助手架构选型”。目标是为有编程基础的新读者生成约3000字中文报告，比较定位、流程控制、工具扩展、会话保存、失败恢复、人工介入和执行环境。确认方案固定使用同一概念例子：读取 `README.md` 和 `pyproject.toml`，回答“如何安装依赖并启动项目”，并说明一次读取失败后的处理。方案不要求运行真实代码或基准测试。

| 环节 | 实际结果 |
|---|---|
| 创建到初稿 | 约00:32创建，00:55生成原生初稿，约23分钟，包含使用者阅读、补检与核对时间 |
| 检索与证据 | 首批2篇摘要；要求简化检索词后新增10条，共12条来源记录。12条证据实际对应7个不同来源 |
| 原生初稿 | 含三方比较表、概念流程和有条件建议；正文含标题表格、排除参考文献，约3106个汉字 |
| 引用核对 | 7篇实际引用均对照原始arXiv摘要页，题名、作者、摘要、日期与版本相符；未阅读全文或验证软件实现 |
| 章节修订 | 初稿遗漏固定案例；正常页面提交修订后补齐，只有选定章节变化，原稿保留 |
| 最终交付 | 约01:05完成采用、定稿和下载，创建到定稿约33分钟；原生Markdown及来源JSON可下载，文件哈希与对应来源记录一致 |

所有检索材料均为摘要与元数据，没有自动取得论文全文、官方仓库正文或明确的软件版本。该技术选型场景需要软件官方文档，不能把此次体验外推为所有科研主题的表现。服务内“定稿”表示固定已审阅版本，不代表证据已经足够支持最终技术选择。

## 做得较好的部分

- 没有把“未找到证据”写成“软件不支持”，也没有编造性能、成本或安全性排名。
- 区分DynaMate2、AutoGen Studio等上层应用与底层框架能力；正确识别与AutoGen无关的“Autogenic网络管理”误命中。
- 引用能够展开对应来源、摘要访问范围、证据位置和相关判断。
- 补检时旧证据仍可查看与下载；修订先生成候选、显示差异，再明确采用，不自动覆盖原稿。
- 文字能解释三种组织思路，并区分运行中状态、持久保存和失败恢复，适合初步学习。

<a id="sci-008"></a>
### SCI-008：官方文档与仓库获取不足

**观察：** 需求明确优先官方文档和仓库，并提供DSH官方仓库链接。当前检索渠道为Crossref、PubMed和arXiv，本次最终仍没有取得官方正文或当前软件版本，许多关键比较项只能标为未知。

**影响：** 用户得到可追溯的初步概览，但会话落盘、重启续跑和工具接入方法等选型问题仍需自行补资料。

**建议与验收：** 开始任务前说明检索渠道与主题的适配程度；支持取得官方网页、仓库及可合法获取的全文，并记录软件版本、提交或资料日期与实际访问范围。使用相同需求验证：关键架构判断能追溯到已取得正文，无法获取的材料保留明确缺口，不能把发现链接当成读过正文。

<a id="sci-009"></a>
### SCI-009：低命中检索需要用户手动纠正

**观察：** 首批复杂检索仅得到2篇间接相关论文，AutoGen查询为0命中。用户要求简化为项目名后，补检新增10条记录，找到AutoGen原始论文等更直接的材料。

**影响：** 不熟悉检索技巧的用户可能过早接受“证据不足”的结果，核心资料覆盖依赖用户主动干预。

**建议与验收：** 低命中时提出或执行预算内的关键词放宽、原始论文优先策略，并解释追加范围。用该主题复测，应能找到核心来源或明确记录合理尝试；不得由0命中推断不存在相关研究。噪声可保留在原始记录中，但不应被当作有效比较依据。

<a id="sci-010"></a>
### SCI-010：确认方案中的固定案例在写作中丢失

**观察：** 方案指定 `README.md`、`pyproject.toml`、安装依赖与启动问题，初稿却改成“项目的配置文件在哪里，读取失败时如何处理”，全文没有两个指定文件名。

**已完成的补救：** 一次正常章节修订补齐了文件、固定问题、位置引用占位符、一次读取失败及三种继续流程。它没有编造真实文件内容、命令或软件API，且其他章节保持不变。

**建议与验收：** 写作前后核对原始需求和确认方案中的具体约束，包括文件名、问题、目标读者与比较维度。相同方案无需用户追加纠正就能保留固定案例；概念设计与实际验证继续区分。单次修订成功不等于需求保留机制已修复。

<a id="sci-011"></a>
### SCI-011：局部修订没有兼顾全篇长度

**观察：** 原稿正文约3106个汉字，补齐共同案例后增至4404，增加1298个。统计含标题和表格、排除参考文献，不等同于排版字数；相对约3000字目标仍明显变长。

**建议与验收：** 章节修订应检查全篇长度及重复内容。若遵守“其他章节不变”会导致明显超长，应在候选中说明，提供精简本节的选项，不能无提示忽略总长度目标。复测局部补充任务时，既保留要求，又给出可理解的长度变化和控制结果。

<a id="sci-012"></a>
### SCI-012：限制说明重复，信息密度偏低

**观察：** 原稿19个论述段中，12个包含“未知”或“证据不足”。比较表、局限部分和结尾再次重复缺口、调查过程与建议。

**影响：** 诚实说明不足值得肯定，但普通读者需要反复阅读相同意思，主要结论不够突出。

**建议与验收：** 开头先交代有条件的结论和适用范围，把重复未知项集中表达。改进后，关键判断仍带必要限定，但同一缺口不再在多个位置完整重复；内部证据组织流程不占据主体篇幅。

<a id="sci-013"></a>
### SCI-013：等待过程与修订完成提示不清楚

**观察：** 补检排队约2分55秒，检索后自动进入另一轮证据整理；运行期间长期只显示“模型生成”。章节修订排队3分29秒、执行1分29秒，完成后仍显示“已提交章节修订”并停在旧版本，需要打开版本下拉框才发现新候选。

**建议与验收：** 清楚展示排队、实际执行、后续自动步骤与已保存结果；提供排队原因或可解释的状态，不强行给不可靠的预计时间。修订完成时应直接出现“修订已完成，查看差异”入口，同时保留原版。离开页面再返回，也能立即辨认当前结果。

<a id="sci-014"></a>
### SCI-014：原生导出不便直接分享

**观察：** 当前页面只提供Markdown和来源JSON，没有Word/PDF入口。下载Markdown缺少独立报告总标题，开头是“任务目标、资料日期与证据边界”；原始文本包含内部claim注释，正文编号在普通Markdown阅读器中不是跳转脚注，需要到文末打开来源链接。

**建议与验收：** 增加Word/PDF，补总标题、日期、摘要和可跳转引用；普通阅读版隐藏内部标记，追溯附件继续保留。导出文件应能独立阅读、分享，且与网页所选版本内容一致。历史本地转换出的Word/PDF不能算网站原生导出能力已通过验收。

<a id="sci-015"></a>
### SCI-015：累计检索与当前预算表达混淆

**观察：** 检索表累计展示6次调用，上方仍写“已用3/3次”；首批0命中的主题在补检取得资料后仍作为缺口显示。预算可能按批次计算，但当前视图没有清楚区分。

**建议与验收：** 按批次展示调用与结果，分别标明当前批预算、累计调用和最新主题覆盖。补检后不再用历史空结果代表当前状态，也不因数字表达混淆诱导用户重复提交。

<a id="sci-016"></a>
### SCI-016：正文与界面日期口径未注明时区

**观察：** 来源记录的UTC时间为11月3日16时段，对应北京时间11月4日0时段。页面采用北京时间，正文却写“资料获取于11月3日”，未注明UTC，容易让读者误解为少检了一天。

**建议与验收：** 统一用户可见时区，或在日期旁明确标注。来源记录、界面和报告应指向同一实际时刻；不能仅因日期跨天就认定资料过期，也不能据此承诺覆盖尚未发生的更新。

## 证据与验证边界

本页依据2026年11月4日正常网页操作、下载文件对比和原始摘要页核对。完整论文、框架代码、并发、断线、所有错误类型及其他学科场景未测试。公开内容仅保留评价所需事实，不包含账户信息、内部任务标识、诊断包或授权链接。
